# Prasunet-hackathon — AML / Fraud Detection Platform

AI-powered anti-money-laundering (AML) transaction monitoring platform for Union Bank of India. Detects multi-hop layering, circular round trips, and smurfing by combining **temporal graph learning** with **sequence modeling**, and produces explainable, investigator-ready alerts.

---

## 1. 🚀 Problem Statement

Traditional AML systems rely on static, rule-based heuristics that are increasingly inadequate against modern, sophisticated financial crime. Illicit actors use complex obfuscation techniques such as **multi-hop layering**, **circular round trips**, and **structuring (smurfing)** to evade detection. These legacy systems suffer from notoriously high false-positive rates, overwhelming investigators and allowing subtle, temporally distributed fraud patterns to slip through undetected. The challenge lies in accurately capturing both the structural complexity of transaction networks and the temporal sequence of account behaviors simultaneously.

## 2. 💡 Solution

Causeway is a full-stack fraud detection and AML platform that overcomes the limitations of traditional systems by combining:

- **A hybrid deep-learning core** — an EvolveGCN-style temporal graph network fused with an LSTM sequence model — that detects multi-hop illicit financial activity in real time.
- **Explainable AI (XAI)** — every alert ships with a SHAP-style narrative, a weighted risk-factor breakdown, and a plain-English summary generated by an LLM.
- **Graph-native intelligence** — a FalkorDB graph database (with an in-memory fallback) powers community detection, shortest-path tracing, and suspicious layering-chain discovery.
- **Semantic search** — pgvector embeddings over alert narratives let investigators find "similar cases to this one" instantly.

What makes it unique is that it doesn't look at an account's transaction history in isolation, nor solely at the static network topology — it continuously evolves its understanding of the graph structure over time while maintaining temporal awareness of individual account sequences.

## 3. 🧠 How It Works

The platform uses a dual-pipeline machine learning architecture:

- **Graph Modeling** — an `EvolveGCNBlock` (evolving graph convolutional network) captures the dynamic topology of money flows across graph snapshots, learning structural embeddings that highlight hidden relationships, layering networks, and circular money trails.
- **Sequence Modeling** — an `LSTM` encoder analyzes the temporal sequence of transactions for individual accounts, capturing behavioral anomalies, frequency surges, and volume irregularities.
- **Hybrid Detection** — graph embeddings are concatenated with LSTM sequence features and passed through dense layers to output a class prediction plus a sequence reconstruction (multi-task learning). Confidence scores and risk factors feed the alerting pipeline.

## 5. 🔍 Features

- **Hybrid ML detection** — EvolveGCN + LSTM model detecting multi-hop layering, smurfing, round trips, dormant-account reactivation, and KYC-mismatch patterns.
- **Explainable AI (XAI)** — SHAP-style narratives and quantitative risk-factor breakdowns (volume surges, network density changes, etc.) for every alert.
- **LLM investigator summaries** — one-click Groq-powered plain-English summaries with recommended actions and risk rationale.
- **Interactive fund-flow graph** — D3.js visualization of transaction networks and entity relationships.
- **Graph intelligence** — FalkorDB-backed community detection, shortest-path tracing, and suspicious layering-chain discovery, with an automatic in-memory fallback when FalkorDB is unreachable.
- **Semantic alert search** — pgvector cosine-similarity search over alert embeddings (deterministic feature hashing — no external embedding model required).
- **Investigation dashboard** — priority queue with status/severity management and an automated feedback loop that feeds retraining.
- **Automated compliance reporting** — ready-to-file STR/CTR reports in standard **goAML XML** format for FIU-IND.
- **Transaction simulator** — generates synthetic transactions to exercise the detection pipeline live.
- **Federated network support** — dashboard for distributed intelligence sharing across federated bank nodes.

## 9. 🧪 ML Details

- **Model** (`backend/ml/model.py`): an `EvolveGCNBlock` (step-projection + GRU evolution) branches on graph snapshots; a two-layer `LSTM` encodes per-account transaction sequences. Branches are fused through dense layers to a softmax classifier, with a secondary sequence-reconstruction head (multi-task, weighted 1.0 / 0.35). Saved artifacts live in `backend/ml_artifacts/`.
- **Features** (`backend/ml/features.py`): parses transactions into sequence features (amount, channel, time deltas) and graph snapshots (adjacency matrices).
- **Inference** (`backend/ml/inference.py`): `infer_alerts()` produces confidence scores, SHAP narratives, and risk factors; a rule-based heuristic layer adds hard signals.
- **Training loop** (`backend/ml/training.py`): `retrain()` builds a fresh dataset from historical alerts + investigator feedback, normalizes matrices, fits the model, and saves updated weights and normalization metadata.
- **Feedback retraining**: confirmations/dismissals from the dashboard are stored in Supabase and incorporated on the next `/retrain` call to adjust class weights and minimize false positives.

## 10. 🚀 Deployment

- **Frontend + API**: build with `npm run build` (`next build`) and serve with `npm start`. Deployable to Render, Vercel, Netlify, or any Node host. A `render.yaml` manifest is included (build: `npm install --legacy-peer-deps && npm run build`).
- **Supabase**: set `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`.
- **FalkorDB**: set `FALKORDB_URL` (Redis protocol). When unreachable, graph intelligence transparently falls back to in-memory traversal.
- **Python ML service**: requires a compute environment with TensorFlow; deploy as an independent container.

## 11. 🛠️ Setup

### Prerequisites
- Node.js v18+
- Python 3.9+ with TensorFlow (for the ML service)
- A Supabase project (Postgres + pgvector)
- Optional: a FalkorDB instance and a Groq API key

### 1. Environment Setup
Copy `.env.local.example` to `.env.local` and fill in:

```env
NEXT_PUBLIC_SUPABASE_URL=https://YOUR-PROJECT.supabase.co
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=your-anon-key

# Python ML service (TensorFlow)
ML_SERVICE_URL=http://127.0.0.1:8790

# Optional: FalkorDB (Redis protocol) + Groq
FALKORDB_URL=redis://default:your-password@your-instance.falkordb.cloud:port
GROQ_API_KEY=your-groq-key
GROQ_MODEL=llama-3.3-70b-versatile
```

Legacy `VITE_*` env names are also accepted as fallbacks.

### 2. Database Setup
Apply the versioned migrations in `supabase/migrations/` (schema, seed data, and the pgvector vector-intelligence migration). Or run the one-shot setup script:

```bash
npm install
node scripts/db-setup.mjs
```

### 3. Install Dependencies

```bash
# Frontend + API
npm install --legacy-peer-deps

# ML Service
pip install tensorflow numpy
```

### 4. Run the Services (concurrent execution required)

```bash
# Terminal 1: Python ML Service (port 8790)
python backend/ml_service.py       # or: python -m backend.ml.server

# Terminal 2: Next.js app (port 3000 — API routes included)
npm run dev

# Optional: legacy Node.js API server (port 8787)
node backend/index.mjs
```

Then open `http://localhost:3000`. The app redirects to `/dashboard`, which loads data from Supabase via the Next.js API routes. The ML service and FalkorDB are optional at runtime — the platform falls back to in-memory heuristics and graph traversal when they are unavailable.
